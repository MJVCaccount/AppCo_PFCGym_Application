The JSON API of the Professional Fighting Championship gym application.

Every route is JSON unless noted. Source of truth for the shapes is src/lib/types.ts; this file is checked against the route files and the real responses by tests/openapi.test.ts.

Success bodies are { "data": ... } with the status shown (two routes differ and say so). Errors are always

{ "error": { "message": "...", "code": "NOT_FOUND", "requestId": "..." } }

code is stable and is what a client should branch on; message is for people and may be reworded. requestId equals the X-Request-Id response header and the server log line.

Authentication is the signed pfc_session cookie set by the sign-in page. There is no token endpoint. A request without a valid session is 401; a signed-in caller whose role may not use the route is 403, except where the id belongs to someone else, which is 404 so ids cannot be probed.

Writes (POST, PATCH, DELETE) must carry an Origin (or Referer) whose host is the application's own, else 403 CROSS_ORIGIN. This check runs before authentication.

Bodies are limited to 100,000 bytes and must be application/json (415, 413, 400); uploads are multipart and limited per route.

Rate limits answer 429 with a Retry-After header in seconds.

Dates are ISO 8601; sessionDate is a calendar date on the gym's own (Johannesburg) calendar.

Daily maintenance (Vercel Cron)

Deletes expired or used password-reset tokens and expired rate-limit counters, drains the email outbox and purges old finished rows. Called once a day by Vercel Cron, which sends Authorization: Bearer <CRON_SECRET>. With CRON_SECRET unset (or shorter than 32 characters) the route answers 404. Safe to run twice.

Erase a member or fighter (POPIA)

Administrators only; irreversible. Replaces the person's name, email and phone, deactivates the account, signs it out everywhere, deletes their documents and the stored files, deletes contact-form enquiries sent from their email address, cancels their future bookings, and writes an audit row that holds no personal data. Bookings, bout offers and the audit trail are kept. Staff accounts and your own are refused with 409.

sessionCookie
